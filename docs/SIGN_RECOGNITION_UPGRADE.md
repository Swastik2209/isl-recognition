# SIGN RECOGNITION UPGRADE — from 7 gestures to 250 pretrained word classes

**Status: COMPLETE and live.** AccessBridge now offers two camera modes: the original seven quick gestures (in-browser, default) and a **250-class ASL word** recognition mode powered by the pretrained winner of Google's *Isolated Sign Language Recognition* competition.

---

## 1. Why the seven-gesture system was insufficient

The original requirement evolved across the project: seven fixed hand shapes are a *communication board* — genuinely useful, instantly responsive, but not sign vocabulary. The explicit ask became: **"at least 50 distinct, genuinely trained word-sign classes, recognised through the actual AccessBridge inference pipeline."**

## 2. What was chosen, and why

After surveying datasets and pretrained models (AI4Bharat INCLUDE videos, Kaggle landmark corpora, Google's `asl-signs` competition data, Hugging Face mirrors), the selected foundation is:

> **`sign/kaggle-asl-signs-1st-place`** (Hugging Face) — the 1st-place solution's `model.tflite` (11 MB, MIT) plus the official 250-sign vocabulary of Google's *Isolated Sign Language Recognition* challenge (CC-BY-4.0 data, 10k+ teams).

Why it wins:

- **Trained by others on Google's own landmark data** — exactly the "companies must have pre-trained data" requirement, with no training run needed on a laptop.
- **Landmark-native**: it consumes MediaPipe landmarks, the same family the browser produces — eliminating the training-data-vs-camera domain gap that caused the historical "hello → paint" mis-recognition with video-trained models.
- **Small enough to run locally**: 11 MB, standard TFLite ops, measured at **~6 ms per window** of inference on 2 CPU threads.
- **Clean licensing**: MIT (model) with attribution preserved; CC-BY 4.0 upstream data.

## 3. The verified model contract

Empirically established with LiteRT (`scripts/inspect_tflite.py`, `scripts/test_dynamic_input.py`):

- Input: **`(T, 543, 3)` float32, dynamic T** (verified T = 8/32/64) — 543 MediaPipe Holistic landmarks per frame ordered **face 468 → left hand 21 → pose 33 → right hand 21**, exactly the column order of the competition parquet data.
- Output: **250 scores** → softmax → probabilities.
- The internal graph (`multi_head_self_attention`, `eca`, temporal convolutions) confirms a sequence model — one prediction per captured window, not per frame.

The packing convention (and the zero-fill for undetected hands) was cross-checked against `louis-she/gislr-live`, a working browser demo of the same competition pipeline.

## 4. Architecture of the live path

```
Browser (Sign to Text → ASL words)
  ├─ 3-2-1 countdown  →  2 s capture window @ 15 Hz
  ├─ MediaPipe Holistic (self-hosted WASM) → 543 landmarks/frame
  ├─ packFrame(): face+lh+pose+rh → (T, 543, 3), missing hands = 0
  ├─ frameHasHands() guard → honest no_hand if nothing detected
  └─ POST /predict  ──gateway──▶  FastAPI (127.0.0.1:3031)
                                    ├─ LiteRT interpreter (model loaded once)
                                    ├─ softmax → top-1 + top-3 + margin
                                    ├─ < 30% confidence → no_match (honest)
                                    └─ structured JSON → UI review card
                                                          ├─ Add to workspace
                                                          └─ one-click insert of alternatives
```

Design decisions with reasons:

- **Countdown pacing (3-2-1-GO)** — inherited from field testing of earlier iterations: an immediate capture window records idle frames and yields confidently wrong words. The window now opens only at GO.
- **Service, not in-browser** — the tflite runs comfortably in LiteRT on CPU; keeping it in a local service means the 11 MB model loads once, the browser bundle stays light, and `tflite-runtime` semantics are exact. Loopback only; no video ever leaves the page.
- **Margin + alternatives in the UI** — a close runner-up is surfaced (and insertable), because the honest answer to "is the top-1 right?" is sometimes "probably, but check".

## 5. Vocabulary integrity

- `src/lib/asl-vocab.ts` is **generated by script** from `sign_to_prediction_index_map.json` (`scripts/gen_vocab.py`) — the UI cannot drift from the model's real classes.
- The UI displays the real count (**250**) from the live service's `/health`, not a hardcoded promise, and marks the everyday-words subset for orientation.
- ASL and ISL labels are never mixed; the ASL basis is stated in the UI and docs.
